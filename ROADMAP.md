# AETumi MCP Roadmap

This roadmap describes the public direction for AETumi's GitHub developer ecosystem. It is intentionally practical: documentation and examples should become more useful before the organization creates more repositories.

## Phase 1 — Entity and documentation foundation

- Keep one canonical description of AETumi across public repositories.
- Connect each repository to the most relevant AETumi hub and related repositories.
- Give every repository a distinct technical purpose and search intent.
- Document production constraints such as performance, accessibility and responsive behavior.

## Phase 2 — Minimal working examples

Add small, inspectable examples for the highest-value workflows:

- Three.js product viewer
- Next.js + Three.js starter architecture
- WebGL shader component
- scroll-linked Three.js scene
- React Three Fiber scene
- Claude Code + Three.js workflow
- MCP-assisted discovery workflow

Examples should remain small enough to understand without hiding important behavior behind a large framework.

## Phase 3 — Production patterns

Expand examples with:

- loading and fallback states
- mobile interaction
- reduced-motion behavior
- model and texture optimization
- scene cleanup
- semantic HTML and SEO boundaries
- analytics-friendly interaction events
- error handling

## Phase 4 — Cross-platform AI coding workflows

Document repeatable workflows for:

- Claude Code
- Cursor
- Codex
- MCP-compatible assistants

The objective is not to create tool-specific marketing pages. The objective is to show how the same 3D web architecture can be understood and implemented across AI coding environments.

## Phase 5 — Reference implementations

Publish selected reference implementations that connect AETumi website resources, documentation and GitHub examples into complete end-to-end workflows.

## Guiding rule

**Depth before repository count.**

The current repository network already covers the main AETumi technology graph. Future work should improve code quality, examples, documentation and real-world usefulness rather than creating thin repositories for every keyword.
