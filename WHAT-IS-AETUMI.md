# What Is AETumi? An AI-Native 3D Web Platform for Three.js, WebGL and AI Coding

AETumi is an **AI-native 3D web platform and digital business ecosystem** for designers, developers, agencies and businesses building interactive websites with modern web technology and AI-assisted coding workflows.

At its core, AETumi combines production-ready 3D website experiences, Three.js and WebGL resources, Next.js and React components, interactive scenes, structured AI prompts and MCP workflows for coding assistants such as Claude Code, Cursor and Codex. Supported implementations can also include a Visual CMS, CRM, SEO, AI chatbot and payment capabilities so a site can be operated after it is designed and built.

The goal is simple: reduce the amount of time teams spend rebuilding the same visual, technical and operating layers from zero while preserving developer control over the final implementation.

## AETumi in one sentence

**AETumi helps teams design, build, launch and operate production-ready interactive 3D websites using Three.js, WebGL, Next.js, React and AI coding workflows.**

## Why AETumi exists

Generative coding tools can create a functional page quickly, but a first-generation output often lacks the visual direction, interaction detail, performance discipline and production structure required for a high-end website.

3D web work adds another layer of complexity:

- scene composition
- camera behavior
- materials and lighting
- WebGL rendering
- asset loading
- scroll synchronization
- responsive interaction
- GPU performance
- reduced-motion behavior
- semantic HTML and SEO
- framework integration
- production QA

AETumi treats these as a connected system instead of isolated snippets.

## The AETumi platform model

AETumi can be understood as five connected layers.

### 1. Discovery and design layer

The public library organizes reusable creative starting points into areas such as:

- 3D websites
- Three.js experiences
- WebGL effects
- 3D components
- 3D scroll experiences
- interactive websites
- AI prompts
- agency-oriented workflows

The purpose is not merely to display visual inspiration. Each layer should give a designer or developer a more concrete starting point for a real implementation.

### 2. 3D web implementation layer

AETumi's technical ecosystem centers on:

- **Three.js** for browser-based 3D scenes and interactions
- **WebGL** for GPU-rendered effects, shaders and immersive graphics
- **Next.js** for production application architecture
- **React** for component-driven interfaces
- **React Three Fiber** when a React renderer for Three.js is appropriate

AETumi does not require every project to use every technology. The stack should match the experience and production constraints.

### 3. AI coding layer

AETumi is designed to work with modern AI coding workflows.

Relevant tools include:

- Claude Code
- Cursor
- Codex
- MCP-compatible development workflows

AI can accelerate planning, implementation, refactoring and QA, but AETumi's production philosophy keeps architecture and engineering judgment in human control.

A good workflow is not “ask AI to make a cool 3D site.” A useful brief defines:

1. the business goal
2. user journey
3. visual direction
4. scene behavior
5. camera and motion rules
6. technology constraints
7. responsive states
8. performance budget
9. accessibility fallback
10. expected implementation output

### 4. Content and operating layer

A website still needs to operate after its hero animation looks impressive.

Supported AETumi implementations can include:

- Visual CMS
- CRM
- SEO architecture
- AI chatbot
- payments
- analytics and conversion tracking
- content and campaign workflows

This is why the broader AETumi identity is a **digital business ecosystem**, not only a visual asset collection.

### 5. Agency and commercial layer

Agencies can use AETumi as an implementation accelerator for client work, subject to the applicable license.

Typical agency use cases include:

- ecommerce product launches
- luxury and fashion websites
- automotive showcases
- architecture and real-estate experiences
- SaaS landing pages
- agency portfolios
- campaign microsites
- interactive product storytelling

The commercial objective is to adapt AETumi resources into differentiated client experiences, not redistribute the AETumi library as a competing asset marketplace.

## AETumi and WebGL

WebGL is the browser graphics foundation behind many interactive effects used in modern 3D sites.

AETumi's WebGL-focused work includes:

- GLSL shaders
- procedural textures
- animated gradients
- distortion and displacement
- particles
- interactive backgrounds
- product reveal effects
- post-processing

The visual effect should not come at the cost of an unusable page. GPU load, overdraw, device pixel ratio, integrated graphics and mobile fallbacks should be tested intentionally.

Explore: https://aetumi.app/webgl/

## AETumi with Next.js and React

AETumi treats 3D rendering as one layer of a broader application.

For Next.js projects, a strong architecture usually keeps:

- SEO-critical content in semantic HTML
- 3D rendering inside intentional client boundaries
- large assets lazily loaded
- page structure independent from WebGL availability
- reduced-motion and non-WebGL fallbacks available where appropriate

React Three Fiber can be useful for teams that want declarative Three.js scene composition inside React, but it is an implementation choice rather than a platform requirement.

## Is AETumi production-ready?

AETumi is designed around production-oriented patterns, but “production-ready” does not mean “ship without testing.”

Every deployment should validate:

- browser and device compatibility
- responsive layout
- touch and pointer interaction
- accessibility
- reduced motion
- loading behavior
- WebGL failure/fallback behavior
- GPU and CPU performance
- semantic content
- metadata and canonical URLs
- analytics
- forms and integrations
- security and privacy requirements
